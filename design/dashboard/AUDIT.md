# 最小产品表达

## 用户需要建立的认识

| 核心表达 | 用户应该理解什么 | 最小呈现 |
| --- | --- | --- |
| 交接 | 这里留着上次的情况和下一步 | 首页一张主卡片，未覆盖部分可展开 |
| 记事 | 这里留着以后还需要知道的内容 | 首页短列表，正文优先 |
| 方法 | 做过的工作可以留下经验或可阅读的步骤 | 一张经验卡片与一个技能阅读示例 |
| 原始依据 | 经验可以回到原始材料核对 | 经验正文与原文并排阅读 |
| 用量 | 这里提供内容大小和模型用量的有限观察 | 可比较比例、分组柱状图、准确数值和计算方式 |

首页不是能力目录。只用这些对象解释 PowerContext 的价值；对象管理、生成和治理不需要在这一阶段全部展开。

三种页面建立三个可复用的布局：概览、阅读与依据、统计。其余功能只有在出现明确用户任务时再决定入口和范围，不按 API 数量铺设页面。

## 用户故事

1. 我回来继续工作：看交接，知道当时记录了什么、下一步和未覆盖部分；再看需要记住的约定。
2. 我想借鉴经验：从方法进入正文，对照原始材料，判断这次是否适用；不把历史记录当作当前指令。
3. 我想核对用量：看差值和覆盖率，展开计算方式和每日汇总；知道估算不等于账单节省。

支付服务与客户访谈共享页面、组件、字段和阅读次序。业务差异只来自正文，不产生另一套导航。

## 图例与语义边界

视觉复现用户提供的白底、蓝色交互、细边框、左侧导航、首页双栏、经验与依据并排和灰蓝双柱。组件由 Tabler 提供，图例决定组件怎样组合及必要的尺寸调整。

只有以下表达需要收紧：

- 交接使用“当时的情况”，不显示当前验证成功的勾选；标题来自保存的 objective。
- 经验标题直接使用 lesson，其余正文使用 situation/action/outcome。没有独立标题、适用条件或限制字段，不额外生成这些字段。
- Experience 的依据关联整条经验，不生成逐句证明、原文高亮或因果流程图。原始内容不足以证明所有结论。
- 技能以原样文本和 validation 呈现，阅读不承诺安装或执行。
- 差值可能为负，零分母不展示百分比，模型未报告的值不填成 0。
- 只展示已知范围；不以全局 scope 列表、组织建立或模型配置为入口前提。

## 最小接口映射

能力判断只依据 `openapi/powercontext.yaml` 和当前实现代码，不采用 RFC。

| 表达 | 现有接口/类型 | 接入边界 |
| --- | --- | --- |
| 范围名称 | `GET /v1/scopes/{scope_id}` | 入口提供已知 ID；不要求全局枚举 |
| 交接 | `POST /v1/handoff-reports/get`；`HandoffContent` | exact selection；report 内部结构按 `builtin/handoff_report/report.py` 适配并检查版本 |
| 记事 | `POST /v1/memory/entries/list`；`MemoryEntry` | 只读 active 正文，不提供写入或列表管理 |
| 经验 | `POST /v1/experience/get`；`ExperienceProposal` | 使用已知精确引用，不承诺搜索、排行或完整目录 |
| 技能阅读 | `POST /v1/skill/get`；`SkillProposal` | instructions 是字符串，不要求固定步骤格式 |
| 原始依据 | `GET /v1/scopes/{scope_id}/sources/{source_type}/{source_id}` | 本原型只展示内建 content 来源；任意正文转义展示，不执行材料里的要求 |
| 用量 | `POST /v1/stats`；`ScopedStats` | exact selection，UTC 预设周期，recall 与 model usage 分开 |

完整目录如需落地，现有 heads 接口还需要分页和按引用读取正文；本次不实现目录。没有把有此 API 视为必须出现此页面。

`server/app.py::_scope_selection_read_access` 对 exact 使用逐范围读取检查，all/subtree 要求 server.observe。普通用户不应为了读取已知范围而必须获得全局观察权限。服务端仍决定内容能否读取，原型不实现角色策略或绕过权限。

## 消融与对抗式评估

| 检查 | 用户仍应能回答 | 设计判断 |
| --- | --- | --- |
| 去掉图标 | 哪里看交接、记事、方法 | 图标辅助定位，文字必须独立成立 |
| 去掉图表 | 差值是多少，哪些记录能比较 | 数字和表格足以核对；图表补充时间分布 |
| 去掉依据入口 | 这条经验的说法能否核对 | 核对能力应明显受损，证明依据入口值得保留 |
| 换成客户访谈 | 当时发生了什么，下次能参考什么 | 产品词不能只适用于工程业务 |
| 原始材料不可读 | 哪些判断暂时无法核对 | 不制造成功状态或伪摘要 |
| 零分母、未知值、负差值 | 数字究竟说明什么 | 不用漂亮数值掩盖数据边界 |

以上是评估判据，不是已经完成的用户研究。自动检查验证交互与数据边界，用户评估决定这些表达是否足以建立正确认识。
