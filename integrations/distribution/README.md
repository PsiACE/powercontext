# Declared Skill resources

`skills/targets.json` selects the complete `powercontext-project-context` Skill for Agent Plugin, Claude Code, WorkBuddy and Codex. It does not select tools, register events or change qualification in `integrations/capabilities.toml`.

Author common guidance in `integrations/agent-plugin/powercontext/skills/powercontext-project-context/`. Author different native guidance in `skills/overrides/<target>/`. Every generated path has one declared source. Keep host-specific Scope, tool availability and permission instructions in overrides. When adding a reference, declare it for each applicable target; unresolved local links fail rendering. Other hosts retain their current authored resources until explicitly declared.

Run `make plugin-skills-check` to inspect checked-in projections. Run `make plugin-skills` to intentionally refresh declared generated repository files. These commands do not contact a Server, download source, install dependencies or modify live host settings. `make check` includes projection verification.

Build a selected complete Skill into an isolated directory:

```bash
uv run python scripts/generate_plugin_skills.py --target codex --output ./build-skills
```

The Skill is at `build-skills/codex/powercontext-project-context/`. It contains all declared resources. Build from the intended Git revision; source/release tooling retains existing package/version coordinates. Generated byte equality proves resource reproduction, not native host discovery or permission.

Check mode reports drift without writing. `--write` intentionally replaces only declared generated files. Add removed generator-owned paths to the target's explicit `retired` list to remove them during refresh; unrelated files are left alone. Do not declare a user-owned or private configuration path as retired. No filesystem scan assigns ownership by filename or content similarity. This is repository generation, not safe deployment over user-edited installed plugins.

Rendering validates every selected Skill and destination before any publication. Each changed file is staged beside its destination and replaced individually. This does not provide a transaction across the whole target or multiple targets; an interrupted developer refresh can be reinspected and rerun. Symlink output paths are rejected. MCP configuration, manifests, adapters and credentials remain outside the generated ownership set.
