# Plugin resource projection evidence

Run `uv run python experiments/usability/distribution/run.py` against immutable baseline `f28f8edfcb2972ac322f4f12b1f224226a9a40ab`; `--baseline` selects another explicit Git revision. The experiment reads pinned Skill bytes through Git and compares pure projections. It neither loads an Agent nor installs a plugin.

The independent variable is resource selection. A universal portable baseline replaces every target with the same four resources. Explicit per-file selection shares only byte-identical sources and keeps host-specific files. The latter reproduces every target exactly; universal copying changes Claude/WorkBuddy guidance and removes Codex `agents/openai.yaml` and `references/experience-skills.md`. An absent broken link is not sufficient evidence of preserved capability: universal copying also removes the entry links and specialized workflows that made those files reachable.

For one synthetic change to the common entry, duplicated copies update only the directly edited target. Explicit source ownership propagates to Agent Plugin, Claude Code and WorkBuddy, which have identical entries, while preserving Codex's specialized entry. Removing Codex's referenced Experience/Skills file yields observable incomplete-package links. Python version and exact outcomes are recorded in `results.json`; no resource-generation performance claim is made.

## Primary source lessons

[#1410 at 48ffe495](https://github.com/oceanbase/powercontext/tree/48ffe495988382360a5b97112ed0b4421dd25907) proposes deterministic projections, but its review explicitly separates common portable Skills from differing downstream capabilities. [#1691 at 3e90e854](https://github.com/oceanbase/powercontext/blob/3e90e8542db8c513c02b13e6f244fa8f070983c2/integrations/distribution/powercontext_integrations/resources.py) generates common tool definitions without a target argument. Actual code and reviews confirm this broad generator can expand host-visible operations; it must not become the source of qualified support. `integrations/capabilities.toml` remains authoritative for maintained support evidence.

[Magpie's Skill implementation at 23d9e5de](https://github.com/yetone/magpie/blob/23d9e5def8c5595c7a8a49df8f2a376084980927/internal/library/skills.go) marks owned copies with hashes, distinguishes owned links/copies from foreign content, and handles platform link differences. Its [shared-Skill tests](https://github.com/yetone/magpie/blob/23d9e5def8c5595c7a8a49df8f2a376084980927/internal/library/shared_skills_test.go) exercise symlink/junction identity and preserving independent copies; [edit tests](https://github.com/yetone/magpie/blob/23d9e5def8c5595c7a8a49df8f2a376084980927/internal/library/skill_edits_test.go) protect user edits from being overwritten on sync. [9fb9a8ab](https://github.com/yetone/magpie/commit/9fb9a8ab8101238752baa748f9e2ccb999407002) fixes edits being undone on restart; [a7e7fe2b](https://github.com/yetone/magpie/commit/a7e7fe2b0f586aa457119d11ee4b672d6720b91d) addresses whole-copy scans during group switching. These are native filesystem tests in the source project, not executed Magpie qualification here. Adopt ownership/conflict discipline; do not adopt bidirectional synchronization for immutable generated repository resources.

[Lody's registry at 811b5733](https://github.com/LodyAI/Lody/blob/811b573329716b23e1144e5d66211ea4ddfb0dfd/packages/shared/src/acp/skills.ts) maps provider-specific discovery directories and bounds scan results. Its [tests](https://github.com/LodyAI/Lody/blob/811b573329716b23e1144e5d66211ea4ddfb0dfd/packages/shared/tests/acp-skills.test.ts) explicitly distinguish verified `.agents/skills` support from unsupported providers. A portable Skill file alone cannot establish host discovery. [Lody Skill documentation](https://lody.ai/docs/skills/) remains read-only discovery, not resource installation.

## Production contract

The repository build-time renderer uses a declarative per-file manifest for Agent Plugin, Claude Code, WorkBuddy and Codex. The Agent Plugin directory remains authoritative for equal-contract resources; explicit override sources preserve all differing current native files. Complete rendering validates local reference reachability before publication. Check mode detects missing/drifting generated repository resources. No new tools, MCP defaults, host registrations, permission rules or support statements are generated.

Repository refresh intentionally updates declared generated files; explicitly retired owned paths can be removed. Foreign files and private MCP configuration remain outside ownership. This does not deploy over user-edited live hosts, require a persistent hash ledger, or promise a directory-wide transaction. The developer selects a Git checkout; rendering does not download rules or infer host capabilities. Runtime synchronization needs its own conflict/recovery design if requested later.
